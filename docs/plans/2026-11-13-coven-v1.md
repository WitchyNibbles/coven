# coven v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use coven's own pipeline as the private toolkit
> does: subagent-driven-development (one implementer per task, a reviewer after each, a final
> whole-branch review). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build coven v1: a public Claude Code plugin and marketplace that ships the build
pipeline skills, a code quality standard, and an agent hierarchy (GM plus background
PMs) with a shared memory store.

**Architecture:** One repo is both the marketplace and the plugin. Skills, agents, hooks and
`bin/coven` are plugin components; a stdlib-only Python package `src/coven/` is the CLI behind
`bin/coven`; `standard/` holds the code standard that `coven project` copies into a repo, and
coven dogfoods it from `.coven/`. Most code is ported from the private toolkit at
the private source repo (its path is in each dispatch prompt; read-only, never modified), cut
down to the spec's scope. Paths below such as `<private>/src/.../project.py` are in that repo.

**Tech Stack:** Python 3.12+ stdlib for the CLI and hooks; POSIX sh for `fail-closed.sh` and
`bin/coven`; pytest, ruff, mypy (strict), pytest-cov, diff-cover via `uv` for development; GitHub
Actions; Claude Code 2.1.224+ plugin format.

**Spec:** `docs/specs/2026-11-13-coven-v1-design.md` (approved 2026-11-13). Read it before your
task; it is the source of every value below.

## Global Constraints

- Python: CLI and hooks use the standard library only and run under `python3 -I`; floor 3.12.
  The standard's `check.py` keeps its own floor of 3.11 (it runs in other people's repos).
- No runtime dependencies in `pyproject.toml` (`[project] dependencies = []`). Dev group only:
  pytest, pytest-cov, pytest-xdist, ruff, mypy, diff-cover.
- Package name in `pyproject.toml`: `covenkit`; import package: `coven`; console script `coven`.
- Names: env vars `COVEN_*`, dirs `~/.config/coven`, `${XDG_CACHE_HOME:-~/.cache}/coven`,
  `.coven/` in repos, temp prefixes `coven-`, printed prefixes `coven <hook>:`. The word
  private toolkit's name appears nowhere in tracked files (the local pattern list enforces it).
- Claude config dir is `${CLAUDE_CONFIG_DIR:-~/.claude}` everywhere.
- Privacy: nothing is copied from the private repo with history. Port by reading and rewriting;
  never carry over a user name, a home path, an email address other than the public author's,
  the name of any private organisation, system or tool, or text for private setups. Fixtures
  are synthetic and written by hand. A local pre-commit hook scans every staged change against a
  private pattern list; if it refuses a commit, fix the text, never bypass it (`--no-verify` is
  forbidden).
- Every test that would reach an outside service fakes it: `claude` (a fake script on `PATH`
  written by the test), `gh` (same), git remotes (a local bare repo in `tmp_path`), the network
  (none). No test reads or writes the real `~/.claude`, `~/.config` or `~/.cache`: tests set
  `HOME`, `XDG_CONFIG_HOME`, `XDG_CACHE_HOME` and `CLAUDE_CONFIG_DIR` under `tmp_path` (a
  `conftest.py` autouse fixture from Task 1 does this).
- Commits: author is the repo-local identity; no `Co-Authored-By` trailer for an agent, no
  "Generated with" line.
- Docs and skill text: plain, short. User names in docs are written `<user>`.

## Review Focus

1. **Malformed hook input** (empty stdin, invalid JSON, missing `tool_input`): deny-secrets
   blocks (exit 2), pm-permissions denies, SessionStart hooks print nothing and exit 0. Tests in
   Tasks 4, 5, 6.
2. **A settings file that is not plain JSON** (comments, trailing comma, a top-level array) or a
   missing `~/.claude`: setup changes nothing and names the file and the parse error; a missing
   directory is created. Tests in Task 8.
3. **Paths with spaces and `~`** in the memory path and repo path: expanded once, quoted in every
   printed command. Tests in Tasks 7 and 10.
4. **`claude` missing or older than 2.1.224** for `pm status`, `pm health`, `doctor`: a one-line
   error naming the found version, exit 1, no traceback. Tests in Tasks 9 and 11.
5. **A repo with no commits, no origin, or a detached HEAD** for the project key and the
   memory-context hook: the key is the main checkout's folder name and the hook still prints the
   user section. Tests in Task 6.
